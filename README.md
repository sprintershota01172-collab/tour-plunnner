# tabi — 旅程プランナー

旅行先を問わず「行きたい場所」を集め、15分刻みで日別の旅程に置くスマホ向けPWAです。初期表示の旅行情報は設定画面で変更できます。

## 使い始める

1. このフォルダをHTTPS対応の静的ホストへ置くか、ローカルでHTTPサーバーを起動します。
2. iPhoneはSafariの共有メニューから「ホーム画面に追加」、Androidはブラウザの「インストール」を選びます。
3. 一度オンラインで開いてから、iPhoneはSafariの共有メニューから「ホーム画面に追加」、Androidはブラウザの「インストール」を選びます。旅程データと写真は端末のIndexedDBに保存されます。

ローカル確認例:

```sh
python3 -m http.server 4173
```

その後 `http://localhost:4173` を開きます。Service WorkerはHTTPSまたはlocalhostで有効になります。

## URL情報の候補取得

ブラウザから他サイトを直接読むとCORSで止まるため、`api/extract.js` にVercel Functions用、同じファイルの `onRequestGet` にCloudflare Pages Functions用の処理を用意しています。Cloudflare Pagesでは `functions/api/extract.js` が `onRequestGet` を公開します。Vercelでは `/api/extract` がこの関数に対応します。Vercelでは `/api/extract` がこの関数に対応します。

候補取得はページのOGPとJSON-LDを読みます。Google Maps短縮URLはリダイレクトを追跡します。住所だけの場合はNominatimを使い、取得結果は必ず候補表示後に利用者が確定します。サイト制限やInstagram等で取得できなければ、URLを保存して名前・住所を手入力できます。

## 共有と保存

- 端末内: IndexedDB（写真も含む）。アカウント登録は不要です。
- 共有: テキスト、PNG画像、JSONの書き出しとJSON読み込み。
- 2台目へ移す場合: JSONを書き出し、もう一方の端末で読み込みます。
- オフライン: アプリ本体と保存済みデータは、一度オンラインで開いた後なら通信なしで利用できます。URL情報の取得とGoogleマップの表示は通信が必要です。

## 動作確認

- 追加: 追加ボタンから名前だけで保存できること。
- 写真: ギャラリー、カメラ、画像貼り付け、ドラッグ&ドロップで追加できること。写真は長辺1600px以内に縮小されます。
- パズル: トレイから時間軸へ置き、15分刻みに整列すること。重なりは拒否され、別日タブへ移動できること。
- 旅程: 日ごとの宿泊帯、開始時刻、Googleマップへのリンク、テキスト/画像/JSON共有。
- オフライン: 一度オンラインで開いた後に機内モードへ切り替え、画面を再読み込みしてページ移動・保存済みデータ・写真が使えること。URL取得と地図リンクは通信再開後に利用します。

## 初期データの仮定

- 2027/2/21〜27の7日間で、2/21と2/27は移動日。
- ハレプナは2/21〜25、ハレクラニは2/25〜26。2/26夜の宿泊先は指定がなかったため、未設定と表示します。
- URL抽出関数の実ホスティングがない環境では、URLの候補取得は失敗扱いになります。入力・保存・JSON共有はそのまま利用できます。
